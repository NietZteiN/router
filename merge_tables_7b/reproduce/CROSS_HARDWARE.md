# CROSS_HARDWARE — the A40 study vs the CISPA A100 rebuild

The master report ([`MERGE_VS_ROUTING_MASTER_2026-07-24.md`](../tofu_sisa_lora/reports/MERGE_VS_ROUTING_MASTER_2026-07-24.md))
measures the original sprint-cluster **A40** study. A day later the 7B k=200 arm was rebuilt from
scratch on **CISPA A100-SXM4-40GB** cards and written up in
[`MERGE_METHODS_7B_K200_2026-07-25.md`](../tofu_sisa_lora/reports/MERGE_METHODS_7B_K200_2026-07-25.md).

That second run is the strongest reproducibility evidence the project has, because almost nothing
was held constant except the code and the seed:

| | A40 run | CISPA A100 run |
|---|---|---|
| Date | 2026-07-24 | 2026-07-25 |
| GPU | NVIDIA A40 (46 GiB) | A100-SXM4-40GB, driver 535.309.01 |
| Stack | older build | transformers 4.48.3 / peft 0.14.0 / torch 2.5.1+cu121 |
| Adapters | the original k=200 pools | **retrained from scratch** (the vendored pools were 0-byte placeholders) |
| Checkpoint root | `/storage2/.../checkpoints` | `$TOFU_CKPT_ROOT/checkpoints_7b` |
| Recipe | `--k 200 --rank {8,32} --epochs 5 --lr 1e-4 --seed 42`, rsLoRA on, q/k/v/o/up/down | identical |

## What replicated

Generated by `python reproduce/verify_report.py --cross-hardware`:

```
  cell                           A40      A100     delta
  base anchor (7B)            0.4260    0.4257   -0.0003
  ft_r32 anchor (7B)          0.7563    0.7420   -0.0143
  additive_mean N=2           0.4596    0.4631   +0.0035
  additive_mean N=4           0.4613    0.4629   +0.0016
  additive_mean N=8           0.4589    0.4616   +0.0027
  additive_mean N=16          0.4601    0.4617   +0.0016
  additive_mean N=32          0.4584    0.4600   +0.0016
  additive_mean N=64          0.4598    0.4612   +0.0014
  additive_mean N=128         0.4591    0.4602   +0.0011
  additive_mean N=200         0.4597    0.4614   +0.0017

  mean delta +0.0001, max |delta| 0.0143 over 10 paired cells
```

**The base anchor lands within 0.0003 and the whole additive N-ladder within +0.0035**, with a
consistent sign (+0.002 mean) that reads as a small systematic offset from the library build rather
than noise. The `ft_r32` ceiling is the loosest cell at −0.0143 (0.756 → 0.742), which is the one
number to quote with a tolerance rather than to three decimals.

Both reports quote 3-decimal values, so the flatness claim in Table D — "population mu is flat in
N" — survives the hardware change intact: the ladder is flat at ≈0.460 on A40 and flat at ≈0.461 on
A100.

## What the rebuild adds

The master report's coverage note deliberately left the 7B k=200 merge battery empty. The A100 run
fills it — see [`../tofu_sisa_lora/reports/MERGE_VS_ROUTING_MASTER_2026-07-24_ADDENDUM_P3.md`](../tofu_sisa_lora/reports/MERGE_VS_ROUTING_MASTER_2026-07-24_ADDENDUM_P3.md)
for the fill-in, and `cells.tsv` rows tagged `run = a100-2026-07-25` for the per-cell record.

The headline consequence for the thesis: **12 more operators, all still in the 0.42–0.45 band**,
and one operator that cannot be run at that scale at all (KnOTS-TIES hangs).

## Why these cells are `rec`, not `PASS`

`verify_report.py` reports the A100 rows as **RECORDED**, not verified. Their JSONs live on the
CISPA cluster under `$TOFU_CKPT_ROOT/checkpoints_7b`, not in `results_snapshot/`, so this repo has
the report's tables but not the underlying files. To close that gap, run the snapshotter there:

```bash
python reproduce/snapshot_results.py --ckpt-root "$TOFU_CKPT_ROOT"
```

and the same cells become checkable.

## A caution about mixing the two

Do not read an A40 number and an A100 number as one series. The rebuild is a *replication*, not a
continuation: it re-measures cells the A40 run already had. Where both exist, `cells.tsv` keeps
them as two rows distinguished by the `run` column rather than collapsing them into one contested
value.
