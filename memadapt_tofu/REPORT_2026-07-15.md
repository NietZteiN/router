# Reproduction Report: "Memory Adapters Enable Fast, Flexible Knowledge Unlearning in LLMs"

**Paper:** Grimes, Kuo, Wu, Smith, Connor (CMU) — ICML 2026 Workshop on Memorization.
**Reproduction:** `~/memadapt_tofu/` on the sprint cluster (1× NVIDIA A40), 2026-07-14/15.
**Research ledger:** `log/memory_adapters/` (4 dated entries, pre-registered hypotheses H1–H9).

---

## 1. The problem and the paper's idea

*Machine unlearning*: after fine-tuning an LLM on many people's data, honor a deletion
request for one person's data — ideally without retraining, and verifiably. Most methods
do post-hoc weight surgery (gradient ascent, preference optimization); these are slow,
approximate, and damage the model.

The paper's idea: make deletion an *architectural* operation. Take a **frozen** LLM and
bolt a **memory layer** onto one MLP layer: a pool of N = 1024² ≈ 1M tiny "memory slots"
(vectors), of which each input token reads only the top-32 selected by a fixed random
router (product-key lookup: two 1024-row key tables whose score sums index the 1M grid,
making lookup O(√N)). Before training, each data source (here: each of TOFU's 200
fictitious authors, 20 QA pairs each) is assigned **256 private slots** — chosen by
TF-IDF over which slots that author's text naturally routes to. During fine-tuning
(only the memory slots train; 15 epochs, lr 1e-2), a gradient mask guarantees each
author's data can only *write* its own 256 slots.

**Unlearning an author = adding their 256 slot IDs to a block-list.** Blocked slots get
score −∞ and are never read again. No gradient steps, milliseconds, reversible, and
even per-query (different users can see different block-lists in one batch). Caveat the
paper itself makes: this is *not* exact unlearning — during training, author B may
*read* author A's slots, so shared knowledge leaks across ownership boundaries.

## 2. What success looks like (TOFU benchmark, forget10 split)

Fine-tune on all 200 authors, then "forget" 20 of them. Four scores (higher = better),
composed from the OpenUnlearning framework's metrics:
**Util.R** (how well the 180 retained authors are still known, relative to a normally
finetuned model) · **Util.G** (general knowledge preserved, relative to the base model)
· **Mem.** (how thoroughly the 20 forgotten authors are *not* memorized) · **Priv.**
(membership-inference attacks can't tell forgotten data from never-seen data, relative
to a from-scratch retrain) · **Agg.** = harmonic mean. The gold standard, "Retrained"
(train from scratch without the 20), scores **0.87 Agg**; the paper claims MemAdapt
matches it: **1.00 / 1.06 / 0.62 / 0.98 / 0.87** — with free unlearning.

## 3. What we built

New flat project `~/memadapt_tofu/` (torch/transformers only, ~2k LoC + 24 CPU tests):

- **`memory_layer.py`** — product-key memory with a key engineering insight: unassigned
  slots are zero forever, so only the 51,200 assigned rows are materialized (compact
  table + pad row + index remap). Bit-exact vs the naive 1M×2048 table; 1.7 GB instead
  of ~34 GB with optimizer states. Whole memory path fp32 (routing identical across
  torch versions), autocast force-disabled inside.
- **Gradient masking** exactly per the paper's pseudocode (dual `embedding_bag` +
  detach trick), with the correct invariant unit-tested: a slot's gradient equals the
  unmasked gradient *from its owner's own sequences only* — cross-author reads shape
  the forward pass but can never write another author's slots.
- **Block-lists** applied on the candidate grid *before* final top-k (so surviving
  slots renormalize — the paper's claimed mechanism for post-unlearn utility gains),
  plus per-query block-lists and optional hard-zeroing.
- **Data pipeline** token-for-token identical to OpenUnlearning's (proven by importing
  their code and comparing), so our model is comparable to their public checkpoints.
- **Eval** through the actual OpenUnlearning framework (pinned env), with the paper's
  four aggregate scores reverse-engineered and **validated offline before any GPU
  spend**: our composed Priv for the public finetuned checkpoint is 0.3810 vs the
  paper's 0.38 — exact; the Retrained anchor reproduces to ≤±0.011 on every axis.

Verification discipline: 24 CPU tests → GPU smoke → calibration gate on public
checkpoints → routing-health gate on the assignment → train → eval. An adversarial
review pass before any GPU time caught a silent killer: OpenUnlearning's eval config
machinery swaps in the wrong base model unless explicitly overridden — every result
would have been invalid while looking plausible.

**Reproduced:** the headline — unlearned Agg **0.869 vs 0.87** (retrain-level quality),
Mem within 0.01, and the central claim: unlearning 20 authors = **0.027 s on CPU**
(vs ≥261 s for the paper's fastest post-hoc baseline). Training: 653 s on one A40
(paper: 1107 s on theirs). The adapter actually *out-learns* full fine-tuning on
retained authors (Util.R 1.075).

**Diverged (outside ±0.03):** Priv 0.917 vs 0.98; Util.G 1.013 vs 1.06; no post-unlearn
utility bump (ΔUtil.R −0.01 vs the paper's +0.07).

## 5. Why the divergence — one mechanism, tested and confirmed by falsification

The paper never specifies the frozen router's initialization scale. Ours lands at
near-maximum entropy: each token spreads its attention almost uniformly over its 32
slots (30.9 effective reads), and 10% of read mass lands on *other* authors' slots.
That single fact explains all three divergences coherently: more usable capacity
(better learning → Util.R 1.075, deeper memorization pre-unlearn), more cross-author
reading (→ forget-knowledge encoded in retained authors' slots → MIA residue → Priv
0.917), and no routing collisions for unlearning to relieve (→ no utility bump).

We then tested the obvious fix (H6): sharpen the router's softmax by scaling the keys
×2/×4 — which turns out to be a *pure temperature* experiment, since uniform scaling
provably leaves slot *selection* unchanged (identical assignments, verified by hash).
Result: **refuted.** Effective reads dropped to 14.9, but Priv never improved
(0.917 → 0.841 → 0.910) and general utility collapsed (1.013 → 0.851). Conclusion:
the leakage is **selection-driven** — down-weighting cross-author reads doesn't help
while the router still selects them. Closing the last gap would require selection-level
changes (smaller top-k, different key geometry) — an architecture choice, not a knob.

## 6. Upstream bugs found (fixed on the `memadapt-eval` branch of open-unlearning)

1. Offline model loading broken: `cache_dir` must point at `HF_HOME/hub`, not `HF_HOME`.
2. Its pinned datasets 3.0.1 cannot read arrow caches written by datasets 4.x
   (isolated pre-built cache added).
3. Its pinned transformers 4.51.3 no longer returns fp32 logits; the metric code
   crashes on bf16 *and* the reference logs assume fp32 — cast restored at the model
   boundary (needed for both correctness and parity).
4. Eval experiment config silently overrides the model choice (`@package _global_`
   merge order) — the adversarial-review catch.

## 7. Verdict and open items

**The paper's core claims replicate:** retrain-quality unlearning (Agg 0.87) at
literally zero cost, on the first full training run, with the strongest privacy score
outside retraining. **The component profile is init-sensitive** in a way the paper
doesn't document: router entropy trades learning capacity against read-leakage, and the
reported Priv 0.98 / utility-bump effects likely live in a sharper-selection regime
than random init gave us. That sensitivity — plus our falsification of the temperature
explanation — is the reproduction's main scientific addition.

Open: seeds 43/44 (variance on the headline), RMU/GradDiff/NPO baseline rows
(~30–40 GPU-h), H8 top-k∈{8,16} selection sweep, H9 (part of the Priv gap may be
metric-composition choice; our alternate composition reads 0.953).

**Artifacts:** checkpoints + evals under `/storage2/jack/checkpoints/memadapt_tofu/`
(sparse ~450 MB each); every run's `meta.json` carries config snapshot, script sha256,
seed, and SLURM job ID. Total GPU spend so far: ≈ 9 GPU-hours.
